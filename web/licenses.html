No third-party JavaScript libraries, images, or media files are bundled. The application JavaScript, HTML, and CSS are part of Songbook itself. The PDF engine and TeX components listed above are shipped only as web/dist/pdf-assets/ and are loaded lazily — nothing PDF-related is fetched until the user first requests a PDF, and the assets contain no song content.

PDF assets

The PDF engine and TeX components are bundled as web/dist/pdf-assets/, built only by web/build-pdf-assets.sh from hash-pinned upstream sources. Their authoritative component record is pdf-assets/manifest.json, which ships with the assets together with the complete corresponding sources (pdf-assets/sources/) and the upstream license files (pdf-assets/licenses/). No PDF assets ship without their manifest and sources.

Release scope note

Cargo.lock also lists dependencies for the command-line and terminal programs, plus build-time-only proc-macro crates. Those crates are not compiled into or distributed with the current browser WASM assets and are therefore not listed as shipped browser components.

The local license files are verbatim copies of the upstream license files. The two Apache-2.0 copies differ only in whether the upstream file includes the optional “How to apply” appendix. The MIT copies differ only in their upstream copyright lines. BaKoMa.txt is the verbatim upstream LICENCE file from the BaKoMa font pack. The PDF assets additionally carry verbatim upstream license files under pdf-assets/licenses/ and their pinned upstream sources under pdf-assets/sources/.
